## 一、概述

### 1.1 范围与编号

- **P1-1 ~ P1-22**：报告 §四 的 22 项 P1，编号与报告一致。
- **A-1 ~ A-3**：从报告 §十「修复带入的已知余留」吸收的 3 项（CLI mcp config runtime-token 通道、MCP scopes 收紧、trust 坏档数据）。
- 共 **25 个工作项**。§十余留其余项（acceptance 写权限、accept/reject 回灌信任、P0-14 幂等、用户∈工作区）为独立切片，**不在本计划**（见 §六）。

### 1.2 执行原则（继承 P0 修复批的成功模式）

1. **按文件域分组、组间互不重叠**，组内可交子代理并行。
2. **i18n 新增键与 openapi 契约再导出由主线程统一收口**，子代理不各自改 `api-types.gen.ts` / i18n 资源文件。
3. **报告标「疑似」的先实机复核再修**（本计划中 P1-10、P1-11 属此类）。
4. **涉及产品口径的不替用户决定**，见 §三裁决项清单；裁决未到前对应项不开工。
5. 每批收口跑该批验证关口（§四），全绿才进下一批。
