# 「使用操作引导」补足方案（2026-10-22）

> 用户反馈：新装后「一进去完全不知道该怎么操作」；现有引导只覆盖**项目初始化**（七步向导：欢迎/工作目录/环境/建项目/连仓库/配 AI/完成），不覆盖**怎么用**（工单怎么建、AI 怎么派、验收怎么过）。本文档为方案提案；按治理铁律，实施前需走 `requirement-intake` 登记能力卡。

## 一、问题定性

现有引导解决的是「**把系统搭起来**」（初始化域），缺口在「**把系统用起来**」（操作域）：

| 维度 | 现状 | 缺口 |
|------|------|------|
| 覆盖时段 | 首登后一次性弹窗 | 进入工作台之后的每个「第一次」无人管 |
| 覆盖内容 | 建项目/连仓库/配 AI | 建工单、派发 AI、审批、验收门禁、看成本/执行 |
| 形态 | 模态向导（7 步） | 无上下文提示、无空态指引、无任务式清单 |
| 入口 | 侧边栏「引导」一项 | 帮助页（/app/help）与场景脱节 |

非专业用户（产品主轴的核心考虑对象）的典型卡点：**建完项目后对着空工作台不知道下一步**。这正对应 2026-10-11 用户评审已识别的「第一公里断 AI 员工」问题的体验侧残段。

## 二、方案设计（三批递进，可独立验收）

### 批一：完成步「下一步」+ 空态行动指引（小，1~2 天）

1. **引导完成步升级**：第七步「完成」页在庆祝文案下追加三张起点卡（点击直接跳转）：
   - 「创建第一张工单」→ 当前项目 /issues 并自动开新建面板；
   - 「把任务派给 AI」→ 工单表单内预聚焦指派 + 帮助提示；
   - 「看看执行与验收」→ /app/executions 或验收页。
2. **空态行动化**：项目工作台/工单列表/执行页的空态从「暂无数据」改为「一句话说明 + 主行动按钮 + 次行动链接」（复用现有空态组件体系）。
3. **验收口径**：新用户从完成引导到发出第一次 AI 派发，全程不需要问「接下来点哪」。

### 批二：上手清单（里程碑 Checklist，中，2~3 天）

1. **形态**：工作台侧栏新增「上手清单」卡（可收起），五个里程碑：
   建项目 ✓（引导已完成）→ 建第一张工单 → 首次 AI 派发 → 首次验收通过 → 查看首次成本报告。
2. **状态驱动**：里程碑完成态由真实数据判定（存在工单/存在 Execution/存在 Acceptance 通过记录/AIUsageLog 有量），完成自动打勾，**不做假进度**。
3. **全勾后**：清单自动收起为一枚徽标（可从帮助页重开）。
4. **持久化**：沿用 onboarding_completed 同模式（zustand persist + 壳镜像），跨端口漂移不丢。

### 批三：上下文提示（Coach Marks，中，2~3 天）

1. **首访高亮**：进入工作台后对 3 个关键控件做一次性气泡提示（带遮罩、点击任意处消失、每处只出现一次）：
   - 全局命令面板（Ctrl+K）——「任何东西都能搜/都能从这里发起」；
   - AI 助理 dock——「直接用自然语言派活」；
   - 通知中心（该你了）——「需要你拍板的事都汇聚在这里」。
2. **触发条件**：批二清单未全勾 && 对应控件未被使用过（localStorage 计数），避免打扰熟手。
3. **豁免**：ESC 全局关闭当日不再出现。

### 配套（随批一先行）

- 帮助页结构化：把「第一次建工单/第一次派 AI/第一次验收」做成三篇场景 how-to（现有 help 模块扩内容，不新增模块）。
- 命令面板加「快速上手」分组：三项里程碑直达 + 重开引导 + 重开上手清单。

## 三、不做的事（边界）

- 不做全屏强制漫游（tour 打断式引导与「渐进展开、不做两套产品」裁决相悖）；
- 不做视频教程/外链依赖（内测期离线可用优先）；
- 不动七步初始化向导的内容与触发语义（2026-10-03 裁决维持）。

## 四、治理与排期建议

- 三批均为前端为主（批二需 server 只读聚合口径或复用既有列表 API 计数，倾向**前端聚合现有查询判定**，零后端改动）；
- 建议 intake 登记为一张能力卡（如 CAP-A-31「使用操作引导」），三批作为切片推进，批一可与下一桌面测试包同行；
- 度量：埋点沿用既有 AIUsageLog/活动流，不做新增埋点系统（上线后人工回访验收）。
