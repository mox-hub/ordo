# 统一创建面板优化方案（2026-10-27）

> **触发**：用户提出对各页面统一创建面板的入口触发按钮做处理、更新实际功能、AI 模式与人工创建模式丝滑切换、冗余内部组件剔除，让创建功能自然流畅且设计/艺术风格符合项目要求。
>
> **范围裁决（2026-10-27 三问三答）**：① 范围=统一面板三批 + 独立创建对话框**标准化**（不并入统一面板）；② 面板内「AI 调度策略」纯 UI 摆设 → **本批移除 UI**（派发链支持审批拦截后随执行批回归）；③ 交付=**只出本方案文档**，实施排期另行决定。
>
> **调研方式**：三路并行探索（面板与入口现状 / AI 与人工创建模式 / 设计宪法与组件库）+ 关键文件亲验（`unified-create-dialog.tsx`、`ui/dialog.tsx`、`mode-shuttle-button.tsx`、`app-store.ts`、`PRINCIPLES.md` §1-§8 视觉条款）。所有 文件:行号 均为 2026-10-27 实测。

## 二、对话框样式与设计规范（先立规后改造）

> 本章把创建面板**现有视觉语言中已达成项目气质的部分提炼为规范**（它们是资产，不是待修项），并给出与宪法的逐条对应 + 现状偏差清单。批二、批四直接引用本章条目号（如「规范 2.6」）。

### 2.1 容器与尺寸：双层体系

| 形态 | 规范 | 宪法依据 | 现状审计 |
|------|------|---------|---------|
| **统一创建面板**（复合工作面：5 实体 × 双模式 × 属性栏） | §20.9 窗口二态制为唯一形态：默认 `w-[min(96vw,720px)]` ⇄ 最大化 `w-[min(96vw,1040px)] h-[min(84vh,760px)]`；禁拖拽 resize、禁最小化 | §20.9 [评审] | ✅ 现实现（L866-868 + Header maximize 钮）即此数值，**固化为唯一形态** |
| **普通实体创建/编辑对话框**（批四 A 级 8 件） | 一律 `ui/dialog.tsx` 的 `size="default"` 档（sm:max-w-md=448 起，消费方可覆盖至 lg/xl/2xl 既成事实档）；禁任意值宽度 | §10.8 | ⚠️ A 级清单中宽度五花八门，迁移时统一取档，「装得下不升档」 |
| **两体系之外** | 禁第三种尺寸形态；宽面板场景（多卡并排）才允许 `size="wide"` | §10.8 | — |

### 2.2 材质与层级

- 面板容器沿用现有毛玻璃语言并固化为创建链路标准材质：`bg-card/95 backdrop-blur-xl + border border-border/70 + shadow-xs`（面板覆写处 L1093-1097）；普通对话框走 `ui/dialog.tsx` 基座默认材质 `bg-popover/95 backdrop-blur-xl + ring-1 ring-border/40`。两者同族（毛玻璃 + hairline），不得再发明第三种面板材质。（§5.2 分层靠背景深浅）
- **投影唯一档**：全链路只许 `shadow-xs`，hover 不抬升阴影，交互反馈交给边框/背景/环色（§3.6）。
- **遮罩**：`bg-black/30 backdrop-blur-sm dark:bg-black/60`，`duration-normal` fade 进出场（dialog.tsx:32 既有）。
- **层级**：一切创建浮层 `z-modal` 档；浮层嵌套禁加 z-index，二次确认一律同层叠加 `AlertDialog`（§8.4 / §20.1）。现脏表单退出确认（L1504-1523）即为范式，保留。
- **禁弹窗内 SectionCard**：子区块用微卡（`rounded-lg border bg-background px-2.5 py-2`）或分区骨架（§20.4）。右栏 PropsCard 已是微卡形态，合规。

### 2.3 布局骨架与密度

面板四区结构固化为规范图（与文件头 ASCII 图同源，L9-22）：

```
┌─────────────────────────────────────────────────────────┐
│  Ordo › [类型 ▾]                        [panel][max][×] │  Header（面包屑 + 窗控图标钮）
├──────────────────────────────────────────┬──────────────┤
│  标题输入（大字号无边框）                  │ Properties   │
│  描述输入（无边框）                        │ （PropsCard  │
│  实体特有字段段（模板自含）                │  微卡+胶囊） │
│  ── AI 建议 / 验收标准（按实体） ──        │ Suggestions  │
├──────────────────────────────────────────┴──────────────┤
│ [连续创建 ⬜]              [穿梭][取消][主按钮 +kbd 提示] │  Footer h-13 bg-muted/15
└─────────────────────────────────────────────────────────┘
```

- 密度口径：§1.3「密度来自单元格（小 padding、密行高），舒适来自区间」——属性胶囊、字段行按高密区紧凑给；主栏输入区、区块间距给足留白。创建面板定性为**极简 chrome + 高密属性区**的混合体，Header/Footer 保持极简（无装饰），右栏属性区按高密区纪律。
- **圆角三档分工**：容器 `rounded-xl`（模态档，§4.5）/ 卡片 `rounded-lg` / 控件一律 `rounded-md`（按钮不因尺寸降档）。ModeShuttleButton 现为 `rounded-lg`（L35）——按「动作按钮一律 rounded-md」核，属偏差，批二修正（它是动作钮不是 chip，不适用 §4.5 胶囊例外）。
- 按钮组间距 `gap-2` 唯一档，footer 禁 `ml-auto` 手摊（§20.8）。现 Footer 左右分组 `justify-between` + 组内 gap 合规。

### 2.4 排版

- 字阶九档唯一阶梯（§3.1），创建链路逐区定档：标题输入 **text-lg**（面板标题档）为基准、最大化态可升至 text-xl；描述输入 text-base（阅读档）；属性值/辅助 text-xs；kbd 快捷键提示 text-3xs 纯 Latin（合规，§2.4 中文下限不适用）。
- 中文文本一律 ≥ text-xs（§2.4）；字重仅 400/500/600（§2.3）；同视图文字层级 ≤ 3 档（§3.5）。
- **偏差核验项**：TitleField/DescriptionField 现字号实施时按九档核对（批二执行，超档降档、缺档补档）。

### 2.5 颜色与状态

- 只许语义 token（§5.1），分层靠背景深浅（§5.2）。
- **accent-purple 锁定 AI 语义**（§5.3 语义色禁当装饰）：创建链路内紫色只出现在「AI 模式可用/激活/AI 产物」上，人工模式 chrome 全中性。琥珀/警示色仅用于就绪度降级等「等人处理」态（§5.3 warning 系 + §22.1）。
- 表单选项（状态/优先级/严重度）一律从 `shared/status/status-visuals` 注册表派生，禁本地枚举与原始色（现 L335-345 已合规，批四迁移件照此办理）。
- 交互三态 token 固定：hover `bg-accent`、selected `bg-accent + text-accent-foreground`、focus-visible `ring-ring`（§8.1）。

### 2.6 模式视觉语言（AI/人工切换的艺术风格基线）

以现 `ModeShuttleButton`（mode-shuttle-button.tsx）为原型固化为双态规范，**批三全部 AI 元素（就绪卡、草稿卡、建议卡）与批四 AI 起草件共用此语言**：

| 态 | 视觉 |
|----|------|
| 人工态（manual） | 中性 chrome：无紫、无光效；穿梭钮呈「可去 AI」的邀请态 |
| AI 态（ai） | `border-accent-purple/40 bg-accent-purple/10 text-accent-purple`，激活加深 `/20`+`/60`；呼吸微光光标（`animate-ping` 双层圆点）；Sparkles 图标 `animate-spin-slow` |
| 通用 | `duration-slow` 过渡；hover 图标 `scale-110`（transform 类动效，§7.2）；`shadow-xs` 不抬升；focus `ring-accent-purple/60` |

- 呼吸微光类动效必须尊重 `prefers-reduced-motion`（§7.4 全局规则，组件不得绕过）。
- 该语言是「AI 在场」的 全仓创建链路统一信号：用户在任何创建入口看到的紫色呼吸 = AI 可用，看到琥珀 = 需要人处理环境问题。

### 2.7 动效

- duration 白名单三档：`duration-fast`(120ms 微交互) / `duration-normal`(180ms 弹出常规) / `duration-slow`(240ms 大面积面板)（§7.1）。分工：Dialog 进出场（fade + zoom-in-95）`duration-normal`（dialog.tsx 既有）；面板内大面积过渡（二态切换、属性栏展开）`duration-slow`（现 L1094 合规）；hover/按压 `duration-fast`。
- 只动 `opacity` 与 `transform`（§7.2）；弹出层用 tw-animate-css 的 `data-*` 变体，framer motion 仅限布局动画，禁三套体系混用（§7.3）。
- 模式切换（manual⇄ai）主栏内容过渡用 `duration-slow` + fade；禁闪切。
- §22.5 活性可感知：AI 生成中必须有呼吸/spinner + `role="status" aria-live="polite"` 播报（P19 修复点）。

### 2.8 触发按钮

- **列表页创建钮唯一形态 = `HeaderActionButton`**（semantic/header-action-button.tsx：圆形图标、hover 展开胶囊，默认 primary 变体）。P13 散点全部收编此形态。
- 空状态创建入口走 `semantic/empty-state` 的 action 槽（§10.6 canonical 空态承载），禁手写空态 div + 裸按钮（P14）。
- 对话框内/面板内触发钮走 `Button` 组件既有变体；`data-ai-action` 标注协议（§12）：提交钮 `create-<实体>`、AI 生成钮 `generate-draft`，kebab-case 动词-对象，全仓唯一。

### 2.9 无障碍与三态

§8.5 八条逐条落地清单（评审必查）：

1. 图标按钮必有 `aria-label`（Header 窗控三钮、穿梭钮已带 title，补 aria 核对）；
2. Dialog 必有 `DialogTitle`（现 L38-41 已有，批二拆分后不得丢）；
3. 表单控件关联 label 或 aria-label，错误 `aria-describedby`；
4. 状态不只靠颜色（AI 紫 + 图标 + 文案三要素）；
5. 焦点可见 `focus-visible:ring-ring`；
6. 焦点管理：浮层打开移入、关闭归还触发元素（base-ui Dialog 默认行为，勿破坏）；
7. 可点击元素语义化 `<button>`；
8. 图片/头像 `alt`。

三态呈现（§10.6）：数据驱动区一律 `AsyncState`；空态 `EmptyState`；**提交中 = 按钮 disabled + 内联 Spinner，禁遮罩**（现 Footer 主按钮 L1481-1485 已是范式）。

## 三、批一：入口收敛（触发层统一）

**目标**：任何页面、任何方式唤起创建面板都是同一条路：`openCreateDialog({ type, projectId, assigneeId })`。

- `GlobalCreateDialog` 宿主（global-create-dialog.tsx）已透传 `type/projectId/assigneeId`，无需结构改动；更新其头注释（「与页面局部实例分工」一段随局部实例消亡而改写）。

### 3.2 深链收敛

- 新 hook `useCreateDialogDeepLink()`（落 `shared/components/create-dialog/` 或 `shared/hooks/`）：封装 `location.state.openCreate + presetAssigneeId` 的渲染期检测 + `replaceState` 清参（P10 两处收编为一行调用）；`?create=…` query 解析同入此 hook。

### 3.3 命令面板与快捷键

**验收点**：6 页创建入口全走 store；深链两处一行化；命令面板可搜「创建」；`n` 键全局唤起；`grep -r "UnifiedCreateDialog" apps/frontend/src/modules` 归零（模块不再直接挂面板）。

## 五、批三：AI / 人工模式丝滑切换

**目标**：两种模式互切零损失、AI 可用性前置可见、AI 元素视觉全链统一（规范 2.6）。

### 5.1 就绪度前置（P17）

AI 界面接 `useAiReadiness`（`modules/ai-hub/hooks/use-ai-readiness.ts`，纯函数 `deriveAiReadiness` 已具备，直接引入）：

| readiness 态 | AI 界面呈现 |
|-------------|------------|
| `loading` | 输入区骨架（AsyncState） |
| `ready` | 现输入区 + 生成流 |
| `unavailable` / `unconfigured` / `unverified` | **AI 就绪卡**替换输入区：诚实说明现状（无可用 provider / 无默认模型 / 默认模型实测失败）+ 双 CTA「去配置」（跳 `/app/settings/ai`）+「转手动创建」（`setMode('manual')`）；输入框不渲染 |
| `unknown` | 输入可用，生成失败走既有可读 400 + `submitViaAssistant` 兜底（P 兜底链保留） |

就绪卡样式：琥珀警示系横幅 + 微卡（§22.1 等人一等三要素：警示色 + 专属图标 + 可计数说明），**不用 AI 紫**——紫=AI 可用，琥珀=等人处理环境（规范 2.5/2.6 的语义分工）。参考 `ai-readiness-banner.tsx` 与 onboarding `CompleteAiReadinessCard` 既有语言，抽公共就绪卡微件候选（若三处形态可归一，立 semantic 件走账本；先面板内实现，归一另批）。

### 5.2 草稿保护（P15/P16/P18）

- **AI→人工**：`onToggle` 去 `setDraft(null)`；有草稿时切 manual 自动 `applyDraftToForm(draft)`（复用 `editDraftManually` 链路），toast「草稿已回填表单」；若目标表单已有实质内容且与草稿冲突，走 `AlertDialog` 确认覆盖（§20.1 浮层串行）。
- **人工→AI**：`generateDraft` 组装 prompt 时附加 `serializeContext()`（模板接口提供）：「当前已填：标题=…、优先级=…、经办人=…，请在此基础上补全/改写」。AI 生成结果视作对已填内容的改写 → 回填前若字段非空，AlertDialog 确认（完整 §22.6 diff 形态列为后续批，`semantic/inline-diff` 已具备承载件）。
- **草稿类型提示**（P18）：草稿确认卡显示目标实体徽标（「将创建：任务」），与当前页签不一致时明示会跳转。

### 5.3 活性与收场（P19）

- 生成中：主按钮 Spinner 既有 + 状态区 `role="status" aria-live="polite"` 播报「正在生成草稿…/草稿已生成」（§22.5）。
- 确认创建成功即关面板 + toast（既有）；`createMore` 连续创建流保留。
- `submitViaAssistant` 兜底：`ready` 态收为次级操作（title 提示保留），不可用态不露出（都不可用无处可转发），`unknown` 态保留主位。

**验收点**：草稿零丢失（AI→人工→提交全链）；表单已填内容进 AI 上下文（生成结果尊重已填）；不可用态一进 AI 模式即见就绪卡（不再白写）；aria-live 播报；模式切换动画 duration-slow。
