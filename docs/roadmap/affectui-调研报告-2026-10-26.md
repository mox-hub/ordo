# affectUI 调研报告 —— 专为 AI 软件设计的 Agent-ready UI 组件库

> 调研日期：2026-10-26。调研方式：官网全站实测（浏览器渲染抓取：首页 / 组件库 / 文档 / 定价 / Agent Tree 组件页）+ GitHub 仓库分析 + 免费组件源码抽查（thinking-loader.tsx）。

## 二、产品定位与设计理念

官网主标语是 **「UI for AI agents」**：*25 React components for what agents do, and 99+ for the rest of your app*。这句话就是它的核心洞察——

1. **「Agent 在做的事」是一种新的 UI 题材**。传统组件库（shadcn/radix/base-ui）解决的是「应用的壳」（按钮/表单/表格），没有人为「一个 Agent 正在跑、正在花钱、正在等你拍板、正在调用工具、正在生成计划」这组体验提供标准化答案。affectUI 把这组体验拆成了 25 个具名组件。
2. **Agents first, the rest of your app too**：不只做 Agent 炫技件，聊天、表格、仪表盘、设置页、Onboarding 等「应用其余 90%」也一并覆盖，且都有 Classic / Clean 双风格。
3. **一文件一组件，代码归你**：每件资产是单个 TSX 文件（样式内含），用 shadcn CLI 装或手动复制，落进项目后完全归用户所有、可随意改。
4. **「Agent-ready」三重含义**：
   - 组件**表达 Agent 行为**（运行态/审批/成本/工具调用）；
   - 组件**可以被 AI 编码助手安装**（MCP server + llms.txt + 每页「Copy prompt to Claude/Codex/Cursor/v0」按钮）；
   - 文档**专门写给 AI 读**（每个组件页有一段「Notes for AI」，明说「把这段给编码助手，替代截图」）。
5. **细节即卖点**：官网反复强调「Same screen, with the details done」——键盘支持、无障碍、暗色模式、reduced-motion、动效语义化是每件组件的标配而非附加。

## 四、Agent 组件族深析（全库灵魂）

25 个 Agent 组件按「治理环节」可归为五组——这个分类学本身就是一份「AI 产品需要哪些治理界面」的需求检查表：

### 4.1 编排与运行可视化
| 组件 | 表达什么 | 交互亮点 |
|------|---------|---------|
| **Agent Tree** | 编排者与子代理的树（即用户所附截图） | 每卡状态/成本/耗时，**成本沿分支向上汇总**，完事分支折叠成一行 |
| Agent Graph | Agent 与工具调用的活网络图 | 每次调用沿连线跑一记脉冲，忙时连线变粗，Agent 工作时「呼吸」、需要人时变琥珀色 |
| Agent Lanes | 每 Agent 一条泳道的实时时间线 | 任务长进「现在」，跨 Agent 交接画线，审批块就挂在时间块上 |
| Agent Queue | 等待执行的作业队列+工人槽位 | 限流暂停时积压深度图上涨、恢复后排空 |
| Fan-out Grid | 一听多发的扇出任务网格 | 每任务一格实时点亮，含重试/失败/成本/剩余时间 |
| Parallel Attempts | 同一任务多路并行竞赛 | 每路一条带模型与方案的赛跑行，评分后择优，可切换 |
| Delegate Board | 拖拽派活给 Agent | 拖上即预览「忙到几点」，Auto 模式自动派给空闲者 |

### 4.2 人机协同与审批（Ordo 的主战场）
| 组件 | 表达什么 |
|------|---------|
| **Approval Card** | Agent 行动前请示：风险徽标+预览+倒计时暂停+批准/拒绝快捷键，批准后平滑形变成已决行 |
| **Permission Request** | 请求某一项具体权利（谁/为何/ exact 会发生什么），允许一次/一小时/永久，之后折叠成一行带剩余时间与 Revoke |
| **Review Center** | 审阅工作台：队列按风险排序、单件聚焦、不稳片段标抖动、A/E/R/S 单键审阅、盖章式离场动画 |
| **Decision Tree** | Agent 卡在决策上，把选项铺成树：每支后果、风险支标记、它自己的倾向高亮，人选一条或自写 |
| **Decision Inbox** | 待决事项收件箱，每条两个快捷答案，答完确认折叠（免费件） |
| **Autonomy Dial** | 三档自治旋钮（自己跑/先问你/锁定必问），Agent 的真实行为在两档间滑动归位 |

### 4.3 透明与可观测
| 组件 | 表达什么 |
|------|---------|
| **Trace Waterfall** | 一次运行的 время与钱花在哪：每次 LLM 调用/工具调用/子代理一根时间线条，逐步 token 与成本，最慢调用标记，分支可折叠回父级 |
| **Tool Call Card**（免费） | 一次工具调用一行：实时计时+状态+摘要，展开看高亮的参数与结果，错误可重试，成组自动汇总 |
| Context Window / Context Map | 模型上下文占用可视化：前者蜂窝格场（悬停点亮、可删文件、compact 时碎格消散），后者 treemap（系统提示/工具/记忆/文件/对话各占一片，compaction 压缩旧轮为摘要） |
| Plan vs Actual | 计划 vs 实际：每步实际条长在虚线计划幽灵上，超时变琥珀，后续步骤右滑，预计完成时刻偏离计划时刻 |
| Agent Ledger | Agent 改过系统里的一切，每条可撤销：前后对照，悬停 Undo 显示连锁影响（什么会被连带撤销、什么不可回退） |
| Conflict Radar | 多 Agent 各占分支并行工作时的冲突雷达：文件×Agent 矩阵，改了同处的 Agent 间连线，每个 Agent 的方案一句话可选，全部裁定后 Merge |

### 4.4 记忆与 Chat 邻接
- **Memory Panel**：助手记住了你什么，分组可编辑，逐条可改/暂停/遗忘+托盘 Undo。
- **Agent Cursors**：Agent 像多人编辑器里的协作者一样在文档里干活——带名指针、逐字打出的建议、调大小的图、修的代码、页边评论。
- **Agent Steering**：运行中转向——排队一条提示等下一步吸收（能看到它滑进计划），或立即打断。
- **Inline Diff**：AI 对文字的修改逐词接受/拒绝（Pro）。
- **Agent Plan**：运行前可评审的计划——改名/拖排序/增删步骤，运行时逐步计时，失败步可重试。

### 4.5 Agent Tree 的 API 设计（组件页实测，代表全库水准）

```ts
type TreeAgent = {
  id, name, task, model?, avatar?, tools?,
  status: "queued" | "running" | "waiting" | "done" | "failed" | "stopped",
  ask?,      // waiting 时需要人裁决什么（"Needs you"）
  error?,    // failed 时错在哪
  cost?,     // 该 Agent 自身成本——有子卡时组件自动汇总整支，勿预汇总
  started?, ended?, children?
};
// 关键 props：collapsed/defaultCollapsed（受控/非受控）、
// onResolve(agent, "approve"|"reject"|"retry"|"dismiss")、onSelect、
// now（时钟注入，避免组件自转定时器）、formatCost
```

设计上值得抄的点：
1. **六态状态机把「等人」(waiting→"Needs you") 当一等状态**，queued/stopped 及其连线自动弱化；
2. **成本是一等公民**：每卡成本+分支 rollup+「成本仍在爬升」的微光动效；
3. **重试语义**：失败 Agent 被重试 = 新 id 的新子节点，失败者保留在树上「讲故事」；
4. 文档五段式齐备：Keyboard 表（Tab/Enter/Space）、Accessibility（ARIA tree/treeitem、needs-you 弹窗是 dialog、汇总数字 polite 播报）、Motion（连线自绘、卡片 glide、reduced-motion 直出）、Responsive（560px 断档、连线从卡片实测防缩放失准）、**Notes for AI**（每次传全树、id 保位、cost 勿预汇总、色板 token 与图标许可提醒）。

## 五、技术实现评估

### 5.1 架构选型
- **React 19 单文件**：每件一个 TSX，只 import React，无 framer-motion/styled-components 等依赖。
- **样式自包含**：用 React 19 的 `<style href="…" precedence="default">`（自动去重 hoist 进 head），主题走 CSS 自定义属性，暗色靠祖先 `dark` class 或 `data-theme="dark"`，尺寸/变体走 `data-*` 属性。
- **响应式用 container queries**（容器查询而非视口断点），嵌入任何布局都自适应。
- **不需要 Tailwind**——这也意味着与 Tailwind 体系集成需要改造（见 §七）。

### 5.2 代码质量实测（抽查 free 层 thinking-loader.tsx）
约 250 行（逻辑+内嵌 CSS），结论：**production 质量**。
- 纯 CSS keyframes 完成全部动效；`role="status"` + `aria-live="polite"` + `aria-hidden` 装饰层 + 完整 `prefers-reduced-motion` 静态降级；
- TS 类型完整：导出 Props 类型、每个 prop 带 JSDoc、union 字面量类型、受控/非受控双模；
- 工程细节讲究：宽度实测双 rAF 平滑形变、zoom 感知 offsetWidth、定时器清理、重试重启逻辑、非显而易见的决策都留了注释。
- 唯一小瑕疵：渲染期读时钟（实践无碍）。

### 5.3 工程化与分发模式（对 Ordo 同样有借鉴价值）
- **shadcn registry 兼容**：`npx shadcn add https://www.affectui.com/r/<item>.json`，也注册了 `@affectui` 命名空间。
- **MCP server**：`claude mcp add --transport http affectui https://www.affectui.com/api/mcp`——Claude Code/Cursor/Codex/VS Code 连一次即可搜索、读文档、代装组件；免费件无需 key。
- **llms.txt / llms-full.txt**：给纯文本偏好的 AI 客户端。
- **每个组件页「Copy prompt」按钮**：一键生成给 Claude/ChatGPT-Codex/Cursor/v0 的安装提示词。
- GitHub 仓库只放免费 57 件作为「实物橱窗」，Pro 件预览+文档全公开但源码 gating——转化漏斗设计干净。

## 七、与 Ordo 的对照分析

### 7.1 技术栈冲突（不能直接搬码的原因）
| 维度 | affectUI | Ordo 现状 | 冲突 |
|------|----------|-----------|------|
| 样式 | 内嵌 CSS + CSS 变量，**无 Tailwind** | Tailwind 4 全仓 + catalog | 直接放入会形成「第四套样式体系」，违反组件治理三层规范 |
| 行为基座 | 自绘交互（无 headless 库） | `@base-ui/react` 行为基座 | a11y 靠作者自证，无 headless 社区背书；复杂件（Data Table/Command Menu）长期维护成本高 |
| 状态 | 纯受控 props（数据全外部给） | TanStack Query + Zustand + WS event-client | **这其实是优点**——受控组件天然适配我们的数据层，只补状态绑定即可 |
| 图标 | Hugeicons Free（MIT，须保留 credit） | 自有图标体系 | 小摩擦 |

| Review Center | 决策收件箱批阅（assistant-decision-tab 已有雏形） | ★★☆ 增强参照 |
| Autonomy Dial | `trust` 信任等级演进的可视化表达 | ★★★ 概念同构 |
| Trace Waterfall | AIUsageLog 成本归因（G8）、execution 步骤流水 | ★★★ 直击 |
| Plan vs Actual | acceptance 验收门禁、执行评估（计划-实际偏差） | ★★☆ |

### 7.3 与现有设计治理的关系
Ordo 已有 design-system 三层（raw/ui/semantic）+ 组件画廊 + registry 门禁 + 36 条组件裁决。引入 affectUI 的正确姿势是**「语义引进、实现自绘」**：把它当「AI 治理界面的语义参考系」，新语义组件按 Ordo 规范（Tailwind + base-ui + semantic 层 + 画廊门禁）自建，而不是把它的 TSX 文件塞进 `components/ui`。若买 Pro，其源码是高质量「参考实现」（250 行级、零依赖、动效全 CSS），改写成 Tailwind 版工作量可控。

## 八、落地建议

**建议按「三步走」，全部走 requirement-intake 闸门立项：**

1. **零成本立刻做：语义与文档范式借鉴**
   - 把 §四的五组分类学对照 `docs/01-需求/能力清单-v1.md` 做一次缺口盘点（重点候选：执行树成本汇总视图、Context Window 可视化、Plan vs Actual、Autonomy Dial 式信任档位 UI）；

   - 「把等人 (Needs you) 当一等状态」「成本一等公民+爬升微光」「失败者保留讲故事的重试语义」三条设计语言直接写进组件裁决记录。

   - `tool-call-card`、`decision-inbox`、`thinking-loader` 等 MIT 免费件可直接取用评估，但需包 Tailwind 适配层或在独立隔离域（如 AI surface 弹层）内先用。

3. **若立项执行可视化大屏（$199 一次性）：买 Pro 作参考实现**
   - Agent Tree / Trace Waterfall / Approval Card / Review Center 四件即值回票价（官网自算：10 件×6h×$75=$4500 自研成本）；买断含全部未来更新与无限商业许可；Ordo 私有仓库改写无再分发问题（若未来开源 Ordo 需复查其 license 条款）。
   - 改写纪律遵守既有裁决：每簇独立小批、禁全库 codemod、语义件进 `semantic/` 层并过画廊门禁。

## 九、风险与限制

1. **单人项目早期风险**：1 位作者、51 commits、295 stars；活跃但生命周期无机构背书。买断制下「作者停更」影响小于订阅制（源码已归你），但生态/MCP/registry 的长期可用性存疑。
2. **无 headless 基座**：键盘/a11y/焦点管理全靠自绘自证，复杂件（Data Table 的单元格选区、Command Menu）的边界行为维护成本会转嫁给使用者。
3. **演示态到生产态的距离**：官网演示是精心编排的假数据；接入真实 WS 推送/查询缓存/错误态需要自建状态层（好在全部受控 props，接线干净）。
4. **双风格（Classic/Clean）维护面**：引进时只取一种风格对齐 Ordo 视觉，避免双轨。
5. **许可边界**：免费层 MIT 无忧；Pro 层是一次性商业许可（非开源），改写后并入私有仓库没问题，**公开再分发受限**——Ordo 未来若开源需复核。

## 十、结论

affectUI 用 25 个 Agent 组件完成了业界第一次对「AI Agent 治理界面」的系统化分类：**运行可见（Tree/Graph/Lanes/Waterfall）、花钱可见（成本一等公民）、出错可救（重试=新子节点）、越权要批（Approval/Permission/Autonomy）、并行冲突可裁（Conflict Radar）、上下文可察（Context Window/Map）**。这套语义与 Ordo「工程化可信度」主轴高度同构，建议：设计语言与文档范式零成本即刻吸收；免费件小额试水；若立项执行监控/决策收件箱深化，$199 买 Pro 改写是高杠杆投入。**不建议**直接引入其文件体系（与 Tailwind 4 + base-ui 体系冲突），一切新功能立项走 requirement-intake。
