# affectUI 免费层逆推 × Ordo 组件库缺口审视

> 方法：clone 官方仓库（MIT，`flohoeller/affectui`，免费层 17 组件 × Classic/Clean 双实现 = 34 文件 + 2 blocks + 4 motion，共 19,340 行）逐件细读，提取可移植工程模式；结合 Pro 件公开 API 文档（前篇已抓全）外推 Pro 实现结构；再以 affectUI 的 25 件 Agents 分类学为镜，对照 Ordo 前端组件库实盘（探索代理盘点：ui 66 件 / semantic 48 件 / raw 3 件 + AI 面组件地图），输出缺口矩阵与分档优化设计。
> 一句话结论：**Pro 不是黑魔法——免费层已经把「模式库」全部交出来了（MIT），Pro 卖的是「具名场景的布局与动效解题」。Ordo 该抄的是模式与语义，不是文件；缺口集中在「执行编排可视化」与「审批操作件」两族，多数可用自有体系自研，Pro 采购从「必选项」降级为「加速剂选项」。**

---

## 一、逆推：免费层源码拆出的 14 条工程模式

以下全部有源码出处（`components/*.tsx`），可直接移植到 Ordo 体系，与 Tailwind/base-ui 不冲突。

### 1.1 组件 API 设计模式

| # | 模式 | 源码证据 | 对 Ordo 的意义 |
|---|------|---------|----------------|
| 1 | **受控/非受控双模**：`const open = openProp ?? openState`，setter 内 `openProp === undefined` 才写本地 state | tool-call-card L95-100 | 我们组件普遍只支持单模；semantic 件升级时补齐此模式可同时服务「表单直用」与「TanStack Query 受控」两场景 |
| 2 | **渲染期状态比对驱动智能自动化**：保存 `prevStatus`，props 变化时在 render 内调整 state（React 官方 adjusting-state 模式） | tool-call-card L103-116：失败自动展开、重跑自动收起，且 `autoOpened` 标记保证「用户手动切换过就不再干预」 | assistant-tool-card / run-status 类组件可用同法做「出错自动展开详情、恢复自动收起」，不引入 effect 链 |
| 3 | **组合式 Group 从 children 读 props**：`Children.toArray(children).filter(isValidElement).map(c => c.props)` 汇总子卡状态 | tool-call-card L232-246：Group 无需 calls 数组 prop，自动产出「Used 3 tools · 2.4s · 1 failed」 | 我们做执行步骤聚合、审批组汇总时，此设计让调用方零样板（直接把卡片当 children 堆进去） |
| 4 | **枚举化语义档位而非裸数值**：`signal: 0\|1\|2\|3`（No/Weak/Good/Strong signal）+ 防御性归一 `level()` 把 NaN/"3"/7/-1 全部收敛到合法档 | smart-recommendation L17-36 | ai-verdict-pill / confidence-bar 现在接受数值；四档枚举对「AI 置信度」这种本就模糊的量更诚实，且天然免疫脏数据 |
| 5 | **空数据 render null 而非 crash**；文案模板用函数而非字符串：`body: (contact) => string` | smart-recommendation L81；email-draft L15 | AI 生成内容天然多变体（tone/长度/语气），函数模板是「一次生成多版供人选」的正确形状 |

### 1.2 状态与时间模式

| # | 模式 | 源码证据 | 对 Ordo 的意义 |
|---|------|---------|----------------|
| 6 | **useStopwatch**：running 时 100ms tick；`startedAt` 由外部注入（服务端时间）；`accumulate` 累加多段运行（重试间歇不计零） | tool-call-card L415-436 | 我们 run-timeline/工具卡的计时各自手搓；统一成此 hook 后「暂停重试累计时长」口径自动正确 |
| 7 | **人性化时长渐进精度**：<1s 显 ms → <60s 显 0.1s → 分/时/天，live 态恒显小数 | tool-call-card L439-447 | 直接抄，全仓统一 formatMs 工具函数 |
| 8 | **Phase 状态机贯穿交互全程**：`"draft"→"sending"→"sent"\|"discarded"`，终态折叠成一行回执+Undo | email-draft L79 | AI 产出审阅件的通用骨架：操作后不是消失，而是「折叠成凭证留痕+可撤销」——这正是我们「AI 同事代写、人确认」缺的收场仪式 |
| 9 | **批阅流水线节奏**：答后 1100ms 确认态→折叠→自动展开下一个折叠项；头部 `aria-live` 播报「3 need your input / All caught up」 | decision-inbox L43-76 | decision-review-modal 批阅多卡片时缺的正是这个「盖章→离场→下一件升起」的节奏与空态庆祝（All caught up） |

### 1.3 渲染与样式模式

| # | 模式 | 源码证据 | 对 Ordo 的意义 |
|---|------|---------|----------------|
| 10 | **零依赖 JSON 高亮**：60 行正则 tokenizer（key/str/num/lit 四类）+ CSS 类着色 | tool-call-card L470-498 | 我们渲染工具参数/结果若引 prism/shiki 是重依赖；此法足够且可控 |
| 11 | **高度封顶三段式**：ResizeObserver 测自然高度 → 超 220px 渐隐+Show all → 全开超 640px 内滚（防 20 万 px 卡片） | tool-call-card L303-347 | LLM 工具结果动辄千行，此三段式是标准答案 |
| 12 | **grid-template-rows 0fr→1fr 无测量高度动画**；`pathLength`+`stroke-dashoffset` 画勾 | tool-call-card L674-684, L656 | 替代我们手写 max-height 猜值或 JS 测量的折叠动画 |
| 13 | **样式卫生四件套**：`all: unset` 重置按钮、`data-*` 属性驱动状态样式、`@media (hover:hover)` 包 hover（触屏防粘滞）、`:where(.dark,[data-theme="dark"])` 零特异性暗色 + 组件级 CSS 变量前缀隔离（`--ui-tc-*`） | tool-call-card CSS 全段 | 我们 Tailwind 体系对应物：`data-[state=]` 变体、`hover` 用 `@media(hover)` 的 base-ui 默认已有；值得吸收的是「状态全部走 data 属性不走 JS class 切换」纪律 |
| 14 | **无障碍三件套**：折叠区 `inert`、状态播报 `role="status" aria-live="polite"`（"${tool} running/finished/failed"）、`prefers-reduced-motion` 全局 1ms 降级块 | tool-call-card L134, L906-918 | 我们 semantic 件 a11y 靠自觉；这三件应写进画廊门禁检查单 |

### 1.4 文件组织模式

- **文件头注释块即产品说明书**（每件开头 8-12 行描述行为细节），正文 JSDoc 全覆盖 props——给 AI 读、给人的 PR 读都友好。
- **一文件多导出**：Card + Group + types 同文件，聚合关系不跨文件。
- **Classic/Clean 双实现是两个独立文件**（非参数化）——同语义两套视觉。对我们启示：主题变体不值得双文件，但「语义件允许有形态变种（featured/compact）」已是我们的既定裁决，方向一致。

## 二、外推：Pro 件是什么、值多少

- 免费层体量：平均 **~570 行/件**（Classic 平均 ~540、Clean 略大），最大 tool-call-card 943/990 行。
- Pro 件在免费层模式之上叠加的是**布局工程**：agent-tree 需要卡片实测定位连线（其文档明说「connectors are measured from the cards」）、分支折叠 FLIP 滑移、成本逐分支汇总；trace-waterfall 需要时间轴刻度/嵌套折叠；conflict-radar 需要矩阵+连线。估算单件 **1200–2500 行**，15 个 screens 为组合件另计。
- **逆推结论**：Pro 的价值 = 具名场景的布局/动效解题（已看到成品交互），模式与代码风格与免费层完全同源。我们拿 MIT 模式库 + 自有 base-ui/Tailwind 体系自研 B 档件（见 §四）完全可行；买 Pro 的意义从「获得能力」降级为「省 2–4 天/件的打磨时间」。

## 三、对照：affectUI Agents 分类学 × Ordo 组件库实盘

Ordo 现状（实盘数据）：`components/ui` 66 件（base-ui 基座）、`components/semantic` 48 件、`components/raw` 3 件；registry 103 条三层 + 10 个 lint 门禁 + 画廊；token 走 `index.css` Tailwind v4 + `status→tone` 三级映射。

### 3.1 已有直接对标（做质量升级，不补缺）

| affectUI | Ordo 现有 | 差距（用 §一模式升级） |
|----------|-----------|----------------------|
| Tool Call Card | `assistant/assistant-tool-card.tsx` | 缺：openOnError 自动展开、Group children 汇总、渐进时长格式、JSON 高亮、高度封顶三段式、inert+状态播报 |
| Decision Inbox | `shared/decision-card/`（card/deck-stack/review-modal）+ `assistant-decision-tab` | 缺：二选一快答范式、答后确认→折叠→自动下一件节奏、aria-live 计数与 All-caught-up 空态 |
| Smart Recommendation | `semantic/ai-verdict-pill`、`semantic/confidence-bar` | 缺：四档信号枚举、alternatives 切换、accept+Undo 收场 |
| Email Draft（AI 产出审阅骨架） | `assistant-opening-report`（部分） | 缺：Phase 状态机+折叠成回执+Undo 的收场仪式 |
| Model Picker | `settings/ai/models-tab`（配置向） | 场景不同：缺「会话内快捷切换+速度/质量/成本三轴即时对比」，低优先 |
| Agent Plan | workflow/Pipeline 相关页 | 形态分散，暂不动 |

### 3.2 有雏形但差距大（升级向）

| affectUI | Ordo 现有 | 差距 |
|----------|-----------|------|
| **Agent Tree**（编排树+分支成本汇总） | `executions/execution-table-view` 是表格；runtime 派发认领已有多 agent 场景 | **缺树形态编排视图**；成本分支汇总语义（双轨成本 Token 轨的可视化落点）完全缺失 |
| **Trace Waterfall** | `run-timeline` 是事件列表；`run-info-panel` 有 `costBreakdown.byModel` 数据 | 有数据无「时间轴条+逐条 token/cost+最慢标记」的瀑布形态 |
| **Approval Card** | `run-approvals-section` + `decision-review-modal`（分散两处） | 缺统一件：风险徽标、行动预览、倒计时暂停、A/R 快捷键、批准后形变收场 |
| Agent Lanes | `ai-surface/pipeline-lane-strip`（演示/回放驱动） | watch-deck 泳道未接真实 Execution 流；「审批块挂时间块上」的交互缺失 |
| Autonomy Dial | `office/trust-tiers-panel` + `adjust-trust-dialog` | 有「等级展示+调整」无「运行时自治边界」概念（哪些动作自己跑/必问）——B-07 三级授权缺 UI 表达 |
| Memory Panel | memory 后端 MemoryAtom + watch-deck 右栏展示 | 缺管理 UI：分组、逐条编辑/暂停/遗忘+Undo |
| Usage Meter | `analytics` 页 + `use-ai-usage` | 有用量无数额语境件（额度/逼近告警/分类堆叠条） |

### 3.3 完全缺失（补白向，按场景成熟度排序）

1. **Context Window / Context Map**——模型上下文占用可视化，前端全缺（ai-hub 有 token 计数数据可喂）。
2. **Permission Request**——细粒度+时效性权限请求卡（允许一次/一小时/永久→折叠一行带 Revoke）；对位 B-07 三级授权的操作面。
3. **Review Center**——按风险排序、单键批阅的审阅工作台（decision-review-modal 是弹窗不是工作台）。
4. **Plan vs Actual**——计划幽灵 vs 实际条、超时琥珀、预计完成偏移；对位 acceptance 执行评估可视化。
5. **Inline Diff**——AI 改文字逐词接受/拒绝；落点：文档模块 document-enhance、PromptEditor。
6. **Agent Steering**——运行中排队提示/立即打断的转向交互；对位 execution 的打断能力。
7. **Agent Ledger / Conflict Radar / Fan-out Grid / Parallel Attempts / Agent Queue / Agent Cursors**——场景未成熟（多 agent 并行改树、批量扇出刚起步），记账候补区，不立项。

### 3.4 治理与文档范式差距（零成本，改门禁即得）

| affectUI 做法 | Ordo 现状 | 动作 |
|---------------|-----------|------|
| 组件页五段式：When to use / When not to use / Keyboard / Accessibility / Motion | 画廊有 demo 无此五段 | 画廊门禁模板增五段（demo 必填 When not to use） |
| **Notes for AI**：每组件页一段「给编码助手的文字摘要，替代截图」 | registry 只有元数据 | registry 每条增 `aiNotes` 字段，生成到 COMPONENTS.md——让 ZCode 代理装件时有准确契约，与 AI surface 主轴互喂 |
| shadcn registry + MCP + llms.txt 分发 | registry 仅内部 lint 用 | 远期可考察把 semantic 件暴露成内部 registry JSON（非本批） |
| 文件头产品说明书注释 + props JSDoc 全覆盖 | 参差不齐 | lint:registry 增「头注释块存在性」软检查 |

## 四、优化设计（分档行动清单）

### A 档：立即可做（不动架构，改现有件，全走小批）
1. **assistant-tool-card 对标升级**：吸收模式 1/2/6/7/10/11/14（自动展开、useStopwatch、formatMs、JSON 高亮、封顶三段式、inert+播报）。
2. **decision-card 族批阅节奏**：吸收模式 9（确认→折叠→自动下一件+All caught up 空态）。
3. **成本展示三件套入 semantic**：`run-overview-card`/`run-info-panel` 的 totalCost/byModel 改造——Number Ticker 式滚动、爬升 shimmer、「分支汇总勿预汇总」语义写进消费约定；沉淀为 `semantic/cost-figure` 一件。
4. **AI 置信度改四档枚举**：ai-verdict-pill/confidence-bar 接受 `signal 0-3` 并内部归一（模式 4），数值口径在展示层折算。
5. **画廊门禁五段式 + registry aiNotes**（§3.4）。
6. **status-visuals 增补 waiting 一等态**：执行/审批「等人」状态在 StatusPill/列表中的视觉权级高于普通暂停态（Needs you 琥珀语义）。

### B 档：立项新建（走 requirement-intake，按价值排序）
1. **execution 编排树**（Agent Tree 语义）：树卡六态（对齐我们 Execution 状态机）、分支成本汇总、失败者保留+重试新子节点；配合体检批派发认领的多 agent 场景。
2. **Approval Card 统一件**：合并 run-approvals-section 与 decision-review-modal 共性为 semantic 件（风险徽标/预览/快捷键/形变收场），两处消费。
3. **run-timeline → 瀑布升级**：AIUsageLog 步骤级 token/cost 上时间轴，最慢调用标记。
4. **Context Window 可视化**（assistant 侧，数据源 ai-hub token 计数）。
5. **Autonomy Dial 化 trust 操作面**（B-07 三级授权的拨盘表达）。
6. **Inline Diff**（document-enhance 场景）。
> B1–B3 若时间紧可考虑 $199 买 Pro 参考实现改写（省 2–4 天/件）；但模式库已在手，自研可控性更高，采购降级为加速剂。

### C 档：明确不做/暂缓
- 直接引入 affectUI 文件体系（无 Tailwind、自绘交互，与 base-ui 行为基座 + 三层治理冲突）；
- Classic/Clean 双文件双风格策略（维护面翻倍，与既有形态变种裁决相悖）；
- §3.3 第 7 条族的六件（场景未成熟，进候补区记账）。

## 五、给组件治理的三条沉淀（写进裁决记录）

1. **语义引进、实现自绘**（前篇结论重申）：affectUI 是语义参考系与模式库，不是依赖。
2. **AI 产出审阅件的标准收场**：操作后「折叠成凭证留痕 + Undo」，禁止无声消失（模式 8/9 泛化）。
3. **「等人」是一等状态、成本是一等公民、失败者保留讲故事**——三条已在前篇提出，本篇补上实现落点：waiting 视觉权级（A6）、cost-figure 语义件（A3）、重试=新子节点（B1 数据契约）。
