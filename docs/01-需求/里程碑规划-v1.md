# 里程碑规划 V1

> 生成时间：2026-08-06
> 依据：任务整理方案 V1（303 条任务）、PRD V3 阶段设计、V2 五层架构、迁移任务清单 T01-T20
> 配套文件：`任务里程碑规划.csv`（每条任务已标记所属里程碑）

---

## 一、规划原则

1. **按架构分层划分里程碑**：基础层 → 业务层 → 能力层 → 执行层 → 治理层 → 扩展层，保证每个里程碑交付后产品都可独立使用。
2. **已完成任务作为基线**：每个里程碑内的 Done 任务视为该阶段已交付内容，继续在飞书中保留记录。
3. **串行为主、允许并行**：核心链路（M1→M2→M3→M4）串行推进；M5（验收治理）的数据层已先行完成，可与 M2-M4 并行。
4. **每个里程碑有明确的完成标志**（Exit Criteria），可据此判断阶段是否收口。

## 三、各里程碑详情

### M1 平台底座（基础层）

- **目标**：平台具备稳定、可观测、安全的基础设施。
- **覆盖模块**：Core（FR-CR）、Auth（FR-AU）、Trust（FR-TRU）、前端基础（FR-COM）。
- **关键任务**：
  - FR-CR-06 可观测性（健康检查/指标）、FR-CR-07 分布式追踪、FR-CR-08 数据库迁移与回滚
  - FR-AU-04 用户注册与导入、FR-AU-05 API Token 管理、FR-AU-06 安全治理、FR-AU-07/08/09/10 企业级认证（OAuth2/SSO/权限 UI）
  - FR-TRU-01/02/03 信任等级与渐进放权
  - FR-COM-09 国际化、FR-COM-10 主题设计系统、FR-COM-11 Kibo UI 接入
  - 页面：PAGE-AU-02 注册页、PAGE-AU-03 SSO 登录页、PAGE-ERR-01 错误兜底页
- **完成标志**：本地登录 + SSO 可用；配置/日志/审计/事件/健康检查/追踪可用；前端布局、主题、国际化就绪。

### M2 业务管理闭环（业务层）

- **目标**：人类 PM 可在平台内完整管理项目-迭代-任务-团队。
- **覆盖模块**：Project（FR-PJ）、Iteration（FR-IT）、Task（FR-TK）、Task Template（FR-TT）、Team（FR-TM）。
- **关键任务**：
  - FR-PJ-09~13（模板/状态机/视图/事件/导入导出）、FR-PJ-21/22/23（Workspace 约束/运营闭环/治理策略）
  - FR-IT-01/02/03 迭代与 Sprint 预算
  - FR-TK-09/10/11（视图/评论/类型体系）、FR-TK-12 任务指派 AI
  - FR-TT-01/02 任务模板与批量创建
  - FR-TM-03~06 团队成员/映射/事件/AI 团队
- **完成标志**：项目→迭代→任务→团队全链路可操作；项目列表/详情/看板、任务、BUG 页面全部上线。

### M3 能力支撑层（能力层）

- **目标**：文档、Git、通知、集成等支撑能力可用，全站页面覆盖。
- **覆盖模块**：Document（FR-DC）、Git（FR-GT）、Notification（FR-NT）、Integration 基础（FR-IG-04~08）、Search/Settings/Help/Desktop/Command Palette/Onboarding。
- **关键任务**：
  - FR-DC-01~11 文档（MDX/版本/关联/审批/导入导出/ContextPack 数据源）
  - FR-GT-01~11 Git（仓库/提交/Diff/动作审批/分支保护/PR/协作闭环）
  - FR-NT-05~09 通知（审批动作/防骚扰/订阅/权限/渠道）
  - FR-IG-04~08 集成配置/外部链接/状态查询/受控写
  - 页面：PAGE-DC/G-T/NT/SEARCH/SET/HELP/INIT/BOOT/AN 等全站页面
- **完成标志**：文档/Git/通知/集成基础可用；路由清单中全部页面有对应实现。
- **建议**：本层与 M2 可并行推进（前端页面与业务模块同步开发）。

### M4 AI 执行闭环（执行层）

- **目标**：外部 Agent 从接入到回写的完整执行闭环。
- **覆盖模块**：Execution（FR-EX）、Runtime（FR-RT）、AI Hub（FR-AI）、Context（FR-CTX）、CLI Dispatch（FR-CD）。
- **关键任务**：
  - FR-EX-01~10 执行建模/审批/步骤/证据/重试/接管/回放/规则引擎/恢复
  - FR-RT-01~11 运行时注册/能力上报/命令执行/审批/CLI/WebSocket/worktree 隔离
  - FR-AI-01~11 模型接入/工作流/对话/MCP 客户端/Skills/ContextPack/任务指派/模型自验收
  - FR-CTX-01/02 上下文四层结构与验收标准注入；FR-CD-01/02 CLI 派发与适配器
- **完成标志**：Agent 可获取上下文→执行→触发审批→回写结果→审计回放；执行/审批中心页面可用。

### M5 验收与治理层（V3 核心）

- **目标**：以 Acceptance 为原子单位的工程治理层（成本/质量/风险/团队活动）。
- **覆盖模块**：Acceptance（FR-AC）、差异化治理（FR-DIFF）、共生集成（FR-IG 接入与同步）。
- **关键任务**：
  - FR-AC-01~07 已实现（数据层/标准/审计/成本归因/ContextPack 注入）
  - FR-AC-08~12 Linear 验收标准同步、证据汇聚、模型自验收、清单社区、分形聚合
  - FR-DIFF-01~14 成本估算/预算/质量权衡/风险预警/质量视图/健康度/决策建议/Sprint 编排
  - FR-IG-01/02/03（GitHub/Linear/Jira 接入）、FR-IG-09~12（双向同步/导入/GitHub Projects/冲突解决）
  - 页面：PAGE-ACPT-01~04 验收中心、PAGE-DASH-01~05 治理仪表盘、PAGE-IG-02 Linear 集成详情
- **完成标志**：PM 可定义验收→完整性审计→执行→证据汇聚→成本/质量/风险视图；Linear/Jira 数据互通。
- **说明**：V3 第一波（T01-T06）在代码层已先行完成，本阶段主要补齐同步、证据、仪表盘与治理深化。

### M6 生态扩展（扩展层）

- **目标**：插件体系与 MCP 服务开放，形成生态。
- **覆盖模块**：Plugin（FR-PL）、MCP Server（FR-MCP）。
- **关键任务**：
  - FR-PL-01~05 沙箱/安装/总线/Manifest/权限审计；FR-PL-10~12 插件市场/权限/版本
  - FR-MCP-01/02 MCP Server 实现与工具/资源定义
  - 页面：PAGE-PL-01/02/03 插件管理/详情/市场
- **完成标志**：插件可安装运行、插件市场上线、MCP 服务可被外部工具调用。

## 四、依赖关系与推进建议

```
M1 平台底座 ──→ M2 业务管理 ──→ M3 能力支撑 ──→ M4 AI 执行闭环 ──→ M6 生态扩展
                    │                 │                  │
                    └──────── M5 验收与治理（可并行）───────┘
```

- **主链路**：M1 → M2 → M3 → M4 → M6 串行；M5 因数据层已先行，可在 M2/M3 期间并行启动（先做 FR-AC-08 Linear 验收标准同步与 PAGE-DASH 系列）。
- **迭代节奏**：每个里程碑拆成 2-3 个 Sprint（用 FR-IT 迭代任务承接），建议 1-2 周一个 Sprint。
- **飞书落地**：导入 `任务里程碑规划.csv` 后，用「里程碑」字段建分组看板；按 M1-M6 过滤，配合「状态」「优先级」排序即可获得阶段视图。
- **风险提示**：M3 任务量最大（74 条，含大量页面），建议优先完成高优先级（紧急/高）任务，Backlog 任务随迭代逐步消化。
