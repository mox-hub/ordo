# 能力收敛计划 v1

> 定位：`能力清单-v1.md` 是每张卡的内容真相，`能力账本-v1.json` 是状态快照，本文件只规定**从 43 张 `doing` 收敛到可交付的施工规则、证据门槛与节奏**。冲突时以能力清单为准。

## 一、基线（2026-10-29）

- 71 张卡：**done 14 / doing 43 / planned 11 / gap 0 / structure 3**（X 桥卡）。
- 结构性问题：`doing` 占 60.6%，`done` 仅 19.7%；大量卡「功能已落地，缺 e2e/实机/证据」长期滞留 doing；没有 WIP 上限，新开工持续挤占收口。
- 收敛的定义：**不是清空 backlog，而是让每张卡到达可被证据证明的终态，或明确退出在制**。

## 二、状态与证据标准

### 2.1 状态机

| 状态 | 准入条件 | 退出条件 |
|------|----------|----------|
| `planned` | 已进能力清单、有卡 ID 与用户任务 | 满足 Ready 后进入 `doing` |
| `doing` | ①六问已答 ②有可测试验收标准 ③有测试映射（GAP-T 或用例）④占一个 WIP 槽位 ⑤卡内有 `下一交付：<可验证物> / <日期>` | 代码合并且证据达级 → `候审`；14 天无提交/无证据 → 回 `planned` |
| `候审` | 已合并 + 门禁绿 + E1/E2 证据齐 | 证据评审通过 → `done`；发现缺口 → 回 `doing` |
| `done` | 证据达级 + 清单状态改为 done + `pnpm ledger:gen` + CHANGELOG 留痕 | 原则上不回退；仅当验收撤销时重开 |
| `gap` | 已知未覆盖、需独立立项 | 转 `planned` 或 `doing` |

### 2.2 证据分级（E1–E3）

| 级别 | 内容 | 适用范围 |
|------|------|----------|
| **E1** | 单测/组件测试，能复现失败路径 | 所有代码卡（强制） |
| **E2** | 集成测试、e2e、契约检查或行为级 API 断言 | 数据/治理/API 卡（强制）；纯前端页需 Playwright 或组件+e2e 组合 |
| **E3** | 打包后实机/干净机/真机验收记录 | 桌面（A-14/A-30/A-31）、移动（M 线）、发版（K-03） |

**豁免**：确实无法自动化的证据，必须在卡内写 `证据豁免：<理由>` + 人工验收记录（日期/环境/步骤/结果）；默认不豁免。仅 E1 的卡不得标 `done`，除非卡内显式豁免 E2。

### 2.3 完成判定（Definition of Done）

一张卡同时满足以下五条才可改 `done`：

1. 代码已合并到 `develop`（或发布分支）；
2. E1 全绿，按 2.2 达到 E2/E3；
3. `pnpm quality:gate` 相关子集绿（至少 type-check + 本模块 test + lint）；
4. 能力清单卡内追加「收口记录」行（日期、PR、证据）；
5. `pnpm ledger:gen` 已重跑，`check:ledger` 绿。

## 三、WIP 与节奏

- **在制卡上限 12 张**（当前 43 → 三批压降）；每个代理/人同时最多 2 张；每张卡同时最多 2 个切片。
- **收口优先于开工**：新开一张卡必须在周会说明「哪张卡让出槽位」。
- 周节奏：
  - 周一 30 分钟 triage：新开工、降级、槽位分配；
  - 周三风险检查：卡住的卡升级人审；
  - 周五证据评审：只审证据，不接受口头“基本完成”；
  - 每周提交 `ledger` diff（done/doing/planned 变化 + 原因）。

## 九、机器化与执行台账

- 状态唯一机器口径：`能力账本-v1.json`（`pnpm ledger:gen` / `check:ledger`）。
- 本周起每张在制卡卡内追加一行：`下一交付：<可验证物> / <日期>`（只对新进入 doing 的卡强制，存量随 triage 补齐）。
- 证据评审记录写在卡内「收口记录」行，不另建台账，避免第二份真相。
- 能力清单状态变更与账本重生必须同一 PR；`check:ledger` 红即阻断。

## 十、风险与例外

- **实机依赖**：A-14/A-30/A-31/K-03/M 线的 E3 受打包与设备环境限制，允许排在 E2 之后，但不得用 E1 代替。
- **跨模块改动**：涉及 decision/document/acceptance 三域的切片，必须同时保留原卡与新卡引用，避免边界规则新增违规。
- **降级不是删除**：`planned` 卡仍保留内容与证据线索；重新启动不重写卡，只追加新切片。
