# Runtime 数据模型草案

## 1. 文档目的

本文件定义 Phase 1 中 Runtime 相关的核心数据模型，回答以下问题：

1. 平台如何识别一个 Runtime
2. Runtime 会话如何建模
3. CLI 会话如何与 `ExecutionRun` 关联
4. 执行、审批、上下文和本地会话之间是什么关系

## 2. 设计原则

- 平台模型优先，不以具体 CLI 工具的数据结构为中心
- Runtime 与执行实例分离建模
- 会话对象和业务对象分离
- 长期身份、短期连接、任务执行三者不能混用

## 3. 核心实体

### 3.1 Runtime

表示一个本地执行节点的长期标识。

建议字段：

- `id`
- `userId`
- `deviceId`
- `displayName`
- `hostPlatform`
- `runtimeVersion`
- `protocolVersion`
- `status`
- `lastSeenAt`
- `createdAt`
- `updatedAt`

### 3.2 RuntimeSession

表示某个 Runtime 在某一段时间内与平台建立的活跃连接。

建议字段：

- `id`
- `runtimeId`
- `sessionTokenHash`
- `status`
- `connectedAt`
- `disconnectedAt`
- `lastHeartbeatAt`
- `connectionMode`

### 3.3 RuntimeCapabilitySnapshot

表示 Runtime 某次上报的能力快照。

建议字段：

- `id`
- `runtimeId`
- `runtimeSessionId`
- `workspaceRoots`
- `providerFlags`
- `cliProviders`
- `capabilityFlags`
- `policyConstraints`
- `recordedAt`

### 3.4 CliProviderDefinition

表示平台认可的某类 CLI Provider 静态定义。

建议字段：

- `id`
- `providerId`
- `displayName`
- `supportsSessionReuse`
- `supportsStructuredOutput`
- `supportsStreaming`
- `status`

Phase 1 首批值：

- `codex`
- `claude-code`

### 3.5 CliSession

表示 Runtime 中某个 CLI Provider 的本地会话。

建议字段：

- `id`
- `runtimeId`
- `runtimeSessionId`
- `providerId`
- `workspaceRoot`
- `status`
- `startedAt`
- `endedAt`
- `lastActiveAt`
- `rawSessionRef`

### 3.6 CliExecutionBinding

表示 `ExecutionRun` 与 `CliSession` 之间的绑定关系。

建议字段：

- `id`
- `executionRunId`
- `cliSessionId`
- `runtimeId`
- `providerId`
- `workspaceRoot`
- `bindingMode`
- `status`
- `createdAt`

### 3.7 ContextPackSnapshot

表示一次执行所使用的结构化上下文快照。

建议字段：

- `id`
- `executionRunId`
- `projectId`
- `taskId`
- `payloadRef`
- `sourceSummary`
- `freshness`
- `createdAt`

### 3.8 ExecutionRun

平台执行主对象，详见：

- `执行审批模型-v1.md`

### 3.9 ApprovalRequest

平台审批主对象，详见：

- `执行审批模型-v1.md`

## 4. 推荐关系

- 一个 `Runtime` 可以有多个 `RuntimeSession`
- 一个 `RuntimeSession` 可以上报多个 `RuntimeCapabilitySnapshot`
- 一个 `Runtime` 可以创建多个 `CliSession`
- 一个 `ExecutionRun` 可以关联零个或多个 `CliExecutionBinding`
- 一个 `ExecutionRun` 关联一个主要 `ContextPackSnapshot`
- 一个 `ExecutionRun` 可以有多个 `ApprovalRequest`

## 5. Phase 1 最小模型

Phase 1 最小建议落地：

- `Runtime`
- `RuntimeSession`
- `RuntimeCapabilitySnapshot`
- `CliSession`
- `CliExecutionBinding`
- `ExecutionRun`
- `ApprovalRequest`
- `ContextPackSnapshot`

## 6. 状态建议

### 6.1 Runtime.status

- `online`
- `offline`
- `unreachable`
- `disabled`

### 6.2 RuntimeSession.status

- `active`
- `expired`
- `disconnected`
- `revoked`

### 6.3 CliSession.status

- `created`
- `active`
- `idle`
- `completed`
- `failed`
- `terminated`

## 7. Phase 1 约束

- 先按单用户绑定 Runtime 建模
- 先按任务级短会话建模 `CliSession`
- 不在 Phase 1 建复杂的多 Runtime 编排关系
