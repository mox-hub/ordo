# 品牌命名方案

> 结论：**Agent Project Manager (apm) 更名为 Ordo**；系列产品采用「母品牌 + 角色词」的**单根词家族**命名。
>
> 本文定位为**品牌命名基线**——后续 CLI / 包 / 桌面 / 文案改名以本文件为口径单一真相源。

## 一、命名定稿

| 项       | 名称                                    | 说明                             |
| -------- | --------------------------------------- | -------------------------------- |
| 母品牌   | **Ordo**                                | 拉丁语「秩序」；开源免费主线品牌 |
| 旗舰产品 | **Ordo**（对外可写作 Ordo Govern）      | 当前 apm 项目——AI 工程治理平台   |
| 组件平台 | **Ordo Kit**（备选后缀 Studio / Build） | 可自由组件的平台                 |
| 去 AI 版 | **Ordo Core**                           | 纯工程内核（无 AI）              |

- **命名规则**：`母品牌 + 角色词`，同一语义场可自由扩展（如 Ordo Lab / Ordo Cloud）。
- **一句话叙事**：*给你和你的 AI 同事，建立同一套工程秩序*——对应产品主轴「AI 同事是手段，工程治理是目的」。
- **CLI 观感**：`ordo`（4 字母、2 音节，像一条 Unix 命令）。

## 二、命名诉求

原名称 `Agent Project Manager`（缩写 `apm`）过长、缩写不语义化。命名需满足：

1. **短**——对标 codex / zcode / trae；约 4-6 字母、1-2 音节，可直接作为 CLI 命令。
2. **语义化**——从名字可读出产品在做什么（AI 工程治理）。
3. **系列可对齐**——主线 + 组件平台 + 去 AI 版共用一套命名逻辑。
4. **合心意 + 展现产品特点 > 商标注册**（产品主打开源免费，练手 + 变现验证）。

定位依据见 [产品差异化策略](产品差异化策略.md) 与 `docs/01-需求/能力清单-v1.md`。

## 三、命名策略：单根词家族（Branded House）

用一个短旗舰名做母品牌，三个产品以**角色后缀**区分功能。

- **取舍**：Branded House vs House of Brands——品牌资产薄的阶段，最省成本的记忆结构是「一个词根反复出现」；三个毫不相干的名字会稀释尚未建立的认知。
- **语义锚点**：`codex` 本义即「法典 / 抄本」，自带「规范 / 秩序」语义——印证短名应落在**治理 / 秩序 / 信任**这个语义场，而非「项目管理」这类功能描述。

## 四、候选方向与评估（过程留档）

### 方向 A — 治理 / 秩序语义（选定）

| 候选     | 长度 | 语义                   | 观感              | 已知撞名                        |
| -------- | ---- | ---------------------- | ----------------- | ------------------------------- |
| **Ordo** | 4    | 秩序（拉丁）           | 克制、Unix 工具感 | 小型牙科 SaaS，消费者级几乎无感 |
| Canon    | 5    | 准则／正典（语义最正） | 权威、经典        | 佳能相机（中文＝佳能，强联想）  |
| Axiom    | 5    | 公理／基本原理         | 硬核、可信        | Axiom Space／分析工具           |
| Tenet    | 5    | 信条／原则             | 有主张            | 诺兰电影／泰尼特医疗            |
| Norm     | 4    | 规范／标准             | 简洁              | 通用英文词、常见人名            |
| Pact     | 4    | 契约／约定             | 干净              | Pact Coffee 等                  |

### 方向 B — 信任 / 证明语义

| 候选   | 长度 | 语义             | 观感           |
| ------ | ---- | ---------------- | -------------- |
| Vouch  | 5    | 担保／背书       | 直接、有承诺感 |
| Attest | 6    | 证明／作证       | 验收感最强     |
| Vigil  | 5    | 守候／守望       | 有守护气质     |
| Vero   | 4    | 真实（意大利语） | 最简洁         |

### 方向 C — 自造短根

词根候选：**Corva / Codra / Vexa / Ordra** + 角色后缀。语义靠品牌故事赋予，可注册性最高，但「展现产品特点」这一条最弱。

### 为何选定 Ordo

- 4 字母 / 2 音节，可作 CLI 命令，观感克制（像 Unix 工具）；
- 拉丁语「秩序」，直指「治理＝给混乱的工程建立秩序」；
- 消费者级撞名低（不像 Canon＝佳能、Tenet＝诺兰电影那种强占用）；
- 与系列后缀（Kit / Core）拼接自然。

## 五、系列架构

```
Ordo（母品牌 · 秩序）
├─ Ordo Govern   旗舰 · AI 工程治理平台（当前 apm 项目）
├─ Ordo Kit      自由组件平台（备选后缀 Studio / Build）
└─ Ordo Core     去 AI · 纯工程内核
```

- 扩展位：Ordo Lab / Ordo Cloud 等，沿用「母品牌 + 角色词」规则。

## 六、改名落地清单

现状规模来自 2026-10-17 全仓扫描（`@apm/` 68 处 / 25 文件；`apm-runtime` 33 处 / 18 文件；`AgentPM|Agent Project Manager` 38 处 / 25 文件）。

| 层                       | 现值                                                                      | 改为                                | 风险                                                       |
| ------------------------ | ------------------------------------------------------------------------- | ----------------------------------- | ---------------------------------------------------------- |
| CLI 可执行名 / 守护进程  | `apm` / `apm-runtime`                                                     | `ordo` / `ordo-runtime`             | 低                                                         |
| 包 scope                 | `@apm/*`（`packages/apm-shared`）                                         | `@ordo/*`（`packages/ordo-shared`） | 中（全仓 import 批量替换，turbo 缓存失效一次）             |
| 根包名                   | `agent-project-manager`                                                   | `ordo`                              | 低                                                         |
| 工单前缀                 | 默认 `APM`（`task.shortIdPrefix`）                                        | `ORDO`（4 大写，合法）              | 低（**仅影响新号**，历史号保留）                           |
| 桌面 appId / productName | `com.agentpm.desktop` / `Agent Project Manager`                           | `com.ordo.desktop` / `Ordo`         | 低                                                         |
| 数据目录                 | `~/.apm`（`installer.nsh` 校验）                                          | `~/.ordo`                           | **高**——需向后兼容（检测旧目录 → 迁移 / 软链），否则丢数据 |
| 前端品牌                 | wordmark `AgentPM`、`index.html` title、i18n 文案、`badgePlaceholderName` | `Ordo` 系列                         | 低                                                         |
| 服务端                   | `openapi.document.ts` title、mail 模板、`prompt-templates`、seed          | `Ordo`                              | 低                                                         |
| 文档                     | `AGENTS.md` / `architecture.md` / `README` / `CHANGELOG`                  | 品牌名同步                          | 中（文档即契约，需同 PR）                                  |
| 环境变量                 | 检查 `APM_*`（各 `.env.example`）                                         | `ORDO_*`                            | 低                                                         |

**关键风险点**

- 数据目录 `~/.apm` → `~/.ordo` 必须做兼容迁移，不能裸改。
- 包 scope 改名会重算 `pnpm-lock` 并让 turbo 缓存失效一次，属预期内一次成本。
- GitHub 仓库名（`agent-project-manager`）**建议不动**——外部引用稳定；品牌显示名只在产品层改。

**执行方式**

- 单分支 `chore/ordo-rebrand`（或 `feat/`），拆两个 PR：
  - PR1 = 代码侧（CLI / 包 scope / 桌面 / 工单前缀 + 数据目录兼容）
  - PR2 = 品牌侧（logo / i18n / 文档 / CHANGELOG）
- 完成后跑 `pnpm quality:gate`。
