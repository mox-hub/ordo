# Phase 1 能力边界矩阵

## 1. 文档目的

本文件用于解决两个常见问题：

1. 第一阶段到底要做什么
2. 哪些能力现在不做，避免范围失控

本文件不是 PRD 的替代品，而是 Phase 1 的收敛工具。

## 2. Phase 1 总目标

Phase 1 的目标不是完成完整 AI 团队系统，而是：

> 打通“人类项目经理 + 外部 AI 开发工具”围绕任务协作的最小闭环。

闭环标准是：

- 人类能创建和管理任务
- 外部 AI 工具能读取结构化上下文
- 外部 AI 工具能创建执行
- 写操作会进入审批
- 执行结果会被回写与审计

## 3. 评估原则

Phase 1 范围判断遵循以下原则：

- 是否直接服务任务执行闭环
- 是否是项目管理底盘的必要能力
- 是否能明显降低后续返工
- 是否会导致产品边界过早膨胀

## 4. 能力矩阵

| 能力域 | 必须做 | 应该做 | 暂不做 |
|-------|-------|-------|-------|
| 项目底盘 | 项目、任务、迭代、状态流、成员、审计 | 依赖关系、知识链接整理 | 全量企业管理能力 |
| Human Surface | 任务管理、主体指派、审批、执行回放 | 风险视图、执行统计 | 复杂组织驾驶舱 |
| Agent Surface | 上下文获取、工具发现、创建执行、提交结果 | 结构化计划模板、失败重试入口 | 对话型工作台终态 |
| 外部接入 | CLI、Codex/Claude Code 适配 | MCP、API/Plugin 基础适配 | 大规模第三方生态市场 |
| 执行模型 | ExecutionRun、ApprovalRequest、ContextPack、审计 | Artifact / Evidence 细化模型 | 多 Agent 调度编排 |
| 权限治理 | 读写分级、动作审批、项目级权限包 | 角色模板、项目级策略覆盖 | 自动晋升与复杂策略引擎 |
| Git / 命令执行（Runtime）| 只读上下文接入、受控动作审批 | 高频常用命令封装 | 全自动代码修改与发布 |
| 项目运营 | 基础执行记录和状态追踪 | 简单周报/风险摘要草稿 | 完整运营自动化闭环 |
| 平台内 AI 成员 | 模型区分字段预留 | 展示层占位 | 正式成员生命周期管理 |

## 5. Phase 1 必须交付

### 5.1 项目管理底盘

必须具备：

- 项目空间
- 任务列表与任务详情
- 迭代管理
- 任务状态流
- 项目成员与基础权限
- 审计记录入口

### 5.2 外部 AI 接入

至少需要：

- 一种 CLI 接入路径
- Codex / Claude Code 首批适配
- 外部 Agent 身份映射
- 项目范围约束

MCP 在 Phase 1 中作为应尽快补齐的下一条主线，而不是首个必须完成项。

### 5.3 执行闭环

必须具备：

- 创建 `ExecutionRun`
- 读取 `ContextPack`
- 创建 `ApprovalRequest`
- 审批通过/拒绝
- 回写执行结果
- 记录执行步骤和审计痕迹

## 6. Phase 1 应该交付

### 6.1 项目体验层

- 执行历史列表
- 审批待办列表
- 执行失败原因展示
- 基础风险摘要

### 6.2 接入体验层

- 工具能力列表
- 上下文模板化输出
- CLI 会话与执行关联

### 6.3 治理体验层

- 项目级权限包配置
- 低风险动作白名单
- 审批原因模板

## 7. Phase 1 暂不做

以下能力应明确排除在第一阶段之外：

- 完整平台内 AI 成员管理
- AI 等级晋升与绩效体系
- 多 Agent 协同调度中心
- 全自动 Git 写入、分支管理、发布流水线
- 复杂 BI 大盘和组织级经营分析
- 面向外部开发者的大型插件市场

## 8. 依赖关系

### 8.1 先有底盘，再有协作

如果项目、任务、成员和审计底盘不稳，AI 协作能力就没有可靠挂载点。

### 8.2 先有执行，再谈自治

如果 `ExecutionRun` 和 `ApprovalRequest` 没有定型，就不应扩展更高级自治能力。

### 8.3 先有 MCP / CLI，再谈生态

如果 MCP 和 CLI 这两条主线没有打通，不应提前投入大型插件生态。

## 9. 验收标准

Phase 1 结束时，至少应满足以下验收条件：

1. 人类项目经理可以在平台内创建任务并分配给外部 AI 工具
2. 外部 AI 工具可以通过结构化方式获取任务和项目上下文
3. 外部 AI 工具可以在平台中创建执行并提交结果
4. 写操作默认进入审批并留下审计记录
5. 人类可以在平台中查看执行历史、审批历史和最终结果

## 10. 后续衔接

如果 Phase 1 验证成功，Phase 2 再扩展：

- Git / Runtime 命令执行 更深接入
- 代码协作闭环
- 更细粒度的风险与失败处理

如果 Phase 2 继续验证成功，Phase 3 再扩展：

- 平台内 AI 成员
- 项目运营闭环
- 更复杂的治理策略
