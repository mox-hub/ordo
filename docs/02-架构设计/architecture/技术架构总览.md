# 技术架构总览

> 本文档是技术分层的精简总览与阅读索引。
> 产品架构与愿景见 [[产品架构愿景]]，需求真相源见 [[产品需求文档-v3|PRD]]。
> v3.0.0（2026-09-07）对齐仓库实况：**pnpm/turbo/catalog 工具链、四应用 + @apm/shared 共享层、34 个后端业务模块与前端模块现状、Runtime 守护进程执行链、工作区多库路由、openapi 契约三件套与并行质量门禁**。数据模型术语沿用 2026-09 重构口径（Task→Issue、ExecutionRun→Execution）。

## 1. 架构原则

- 模式：Client-Server + REST + WebSocket。
- API 前缀：`/_api`；Swagger `/_api/docs`；契约导出 `/_api/openapi.json`。
- 部署：可单进程托管前端静态产物（`FRONTEND_DIST_DIR`），亦可前后端分离。
- 治理原则：文档先行、契约驱动、测试可追溯；单真相源（代码/设计文档/PRD 冲突时人工裁决）。
- UI 原则：主线 `@base-ui/react` + shadcn 生成组件 + Tailwind 4；`components/{ui,brand,icons}` 为组件根；`@radix-ui` 与 `kibo-ui` 已退场。
- 主体模型：统一三类主体 `human` / `platform_ai_member` / `external_agent`（Member 统一身份），见 [[角色级权限模型-v1]]。
- 工具链：pnpm workspace + catalog 版本集中 + turbo 任务编排 + husky/lint-staged。

## 2. Monorepo 物理结构（pnpm 11 + turbo 2 + catalog）

```
agent-project-manager/
├── apps/
│   ├── server/        # NestJS 后端（REST + WS + 数据层）
│   ├── frontend/      # React SPA（监督/审批/文档/AI 面板）
│   ├── cli/           # @apm/cli：瘦客户端(apm) + 常驻守护进程(apm-runtime)
│   └── desktop/       # Electron 桌面壳（托管前端 + runtime 的体验增强层，ADR-014）
├── packages/
│   └── apm-shared/    # @apm/shared：CLI 与 runtime 共用协议/适配器/http/配置/错误/生成类型
├── openapi.json       # 契约真相（根仓库，供 contract:check / 双端类型生成）
└── scripts/           # 质量/巡检脚本（contract/api-audit/docs-sync/cli-contract/...）
```

| 组件 | 技术 | 职责 |
|------|------|------|
| `apps/server` | NestJS 10 + Prisma 6 (SQLite) | 控制面 REST + 实时 WS + 执行核心 + 数据层 |
| `apps/frontend` | React 19 + Vite 7 + Tailwind 4 | 人类控制面（web） |
| `apps/cli` | Node + commander + socket.io-client | Agent 侧入口：`apm` 命令 + `apm-runtime` 守护进程 |
| `apps/desktop` | Electron 44 | 桌面壳（shell），托管前端与本地能力（ADR-014） |
| `packages/apm-shared` | 框架无关 TypeScript | 协议镜像、CLI adapters（codex/claude-code/zcode）、HTTP 客户端 |

## 3. 双表面技术分层

> 对应 [[产品架构愿景|产品架构愿景第二章]]。两个表面共享同一套后端服务与执行核心。

```
┌──────────────────────────────────────────────────────┐
│  Human Surface   React Web UI（监督/审批）+ Desktop 壳 │
├──────────────────────────────────────────────────────┤
│  Agent Surface   @apm/cli（命令）· MCP 接入 · apm-runtime │
└──────────────────────────────────────────────────────┘
            ↓ 共享后端（REST /_api + WS）↓
┌──────────────────────────────────────────────────────┐
│  Execution Core  NestJS + 36 业务模块目录 + 事件总线    │
└──────────────────────────────────────────────────────┘
            ↓ 派发执行（cli-dispatch）↓
┌──────────────────────────────────────────────────────┐
│  Local Runtime   apm-runtime 守护进程 → CLI Adapters   │
│                  (claude-code / codex / zcode)        │
└──────────────────────────────────────────────────────┘
```

## 4. 系统分层

### 4.1 后端（NestJS + Prisma/SQLite）

- `core/`：config、crypto、database、logger、message-bus（事件总线）、audit、tracing、exceptions。
- `common/`：guards、filters、pipes、interceptors、decorators、security、throttler、utils、dto。
- `gateways/`：`events.gateway`（socket.io 实时事件推送）。
- `generated/`：i18n 生成资源；`i18n/`：nestjs-i18n 多语言。
- `modules/`：**40 个业务模块目录**（42 个业务 Module 类——`auth` 拆 `access-token`、`document` 拆 `document-enhance`；`contract`/`release`/`profile`/`playbook` 为 2026-09 增量，全量挂载），按域归类：

| 域 | 模块 | 说明 |
|---|---|---|
| 身份与访问 | `auth` | JWT + OAuth2 + PAT（AccessToken） |
| 用户/团队/角色 | `user`、`team`、`role` | Member 体系、ProjectRoleDefinition（executionRole/promptHint） |
| 项目与工作区 | `project`、`workspace`、`metadata`、`config` | 项目 CRUD、多库工作区管理、标签/状态定义、AppConfig |
| 工单域（Task/Bug 统一） | `issue`、`issue-type`、`issue-template`、`iteration` | Issue 统一模型、IssueType 适配引擎(customFields)、模板、迭代 |
| 文档与知识 | `document`(+`document-enhance`)、`activity`、`subscription` | 富文档(section/version/approval/task-link)、动态追踪、订阅 |
| AI 执行编排 | `ai-hub`、`execution`、`runtime`、`cli-dispatch`、`cli-provider`、`skills`、`context` | ContextPack 策展、Execution 状态机、runtime 注册、CLI 派发、技能 |
| 治理与验收 | `acceptance`、`trust`、`decision` | 验收契约、信任评分、DecisionProposal |
| 协作与记忆 | `collaboration`、`memory`、`office`、`dashboard`、`profile`、`playbook` | 接口协作卡、MemoryAtom、办公聚合、仪表盘、项目档案与考古、剧本 |
| 契约知识 | `contract`、`release` | 契约文件绑定（managed/synced/detached）、种生三件套、发版与 CHANGELOG 单向再生 |
| 集成与能力 | `integration`、`git`、`mail`、`mcp-server`、`notification`、`plugins`、`admin` | GitHub/Linear/Jira、Git、MailOutbox、MCP Server、通知、插件、运维 |

> 注：原 `terminal` 模块已废弃并入 `runtime`（Provider Capability）。

**数据层与工作区多库**：
- Prisma 6 + SQLite（`PRISMA_CLIENT_ENGINE_TYPE=library`），单 `dev.db` 之外的**工作区化存储**由 core/database 承载：
  - 工作区 = 用户指定目录（含 `data/apm.db`、`uploads`、`logs`、`workspace.json`），`workspaces.json` 注册表统一登记；
  - 请求经 `x-workspace-id` 头 → `workspaceALS`（AsyncLocalStorage）→ 数据层按工作区路由到对应 SQLite 库；`default` 工作区即 `DATABASE_URL`；
  - 新工作区以 `prisma/template.db` 为模板复制初始化（`pnpm build:template-db`）。

### 4.2 前端（React + Vite + Tailwind 4）

- `app/`：路由（`router.tsx`，React Router v7）；`main.tsx` 入口。
- `modules/`（Feature-based，37 个模块目录）：acceptance、activity、admin、ai-hub、analytics、assistant、auth、boot、config、contract、core-config、decision、delivery、design-system、desktop、document、execution、executions、git、github、help、integration、issue、linear、mcp-server、notification、office、onboarding、project、project-role、runtime、search、settings、skills、task-template、team-member、workspace。其中 `assistant` 为主 AI 面板，`issue` 为看板/详情（含 Bug），`decision`/`office`/`workspace` 为新协作域，`contract` 为契约绑定面板（2026-09 增量）。
- `components/`：`ui/`（base-ui/shadcn 基础组件）、`brand/`、`icons/`；`modules/design-system` 承载 token/语义/图标与治理脚本。
- `infrastructure/`：`api-client`（含 `generated/api-types.gen.ts` 契约类型）、`event-client`（socket.io）、`store`、`hooks`。
- 状态：TanStack Query v5（服务端状态）+ zustand（本地状态）；表单 react-hook-form；MDX/CodeMirror6 编辑器链路；react-i18next（zh/en 双语）。
- 测试：Vitest + Testing Library + msw + jsdom；E2E：Playwright（storageState 登录态，全用户可达模块覆盖）。

### 4.3 控制面与本地执行面（Runtime / CLI 链）

- **Server 侧**：`runtime` 模块登记在线 Runtime（注册/心跳/capabilities）；`execution` 承载 Execution 八态状态机（draft→…→completed/failed/blocked）与审批（ApprovalRequest）；`cli-dispatch` 按项目角色/CLI provider 解析并组装 prompt，经 REST/WS 下派给**在线 runtime**。
- **Runtime 侧（apps/cli）**：`apm-runtime` 守护进程单实例运行（`runtime.lock` 原子锁 + 陈旧接管），`worker` 消费派发队列、维护审批映射、进程树取消、事件与结果回传；通过 REST（`/runtime/*`）+ WS（`/runtime/ws`）与 Server 双向通信。
- **CLI adapters（@apm/shared）**：`claude-code` / `codex` / `zcode` 三适配器 + `process-runner`，框架无关（仅依赖 child_process），协议 DTO 在 `@apm/shared/src/runtime/protocol.ts` 与 server 端**镜像同步**。
- **执行闭环**：Execution → 派发到 Runtime → CLI adapter 执行 → execution events/result 回传 → **Acceptance 验收门禁**收口（非完成即放行）。
- **Web 控制面**：项目、工单、验收、审批、审计、配置、ContextPack 策展（AI Hub）、AI 面板。

## 6. Core 基础设施能力

- **事件总线**：`@nestjs/event-emitter` 领域事件统一流转。
- **审计**：统一审计入口，不可篡改，支持按 executionRunId 聚合。
- **可观测性**：健康检查、统一日志（winston/LoggerService）、tracing（请求链路）、指标暴露。
- **配置**：分环境配置（ConfigService）、关键配置校验、敏感配置脱敏。
- **数据库**：Prisma 6 + SQLite + 工作区多库路由（workspace-registry / template.db / ALS）。
- **错误模型**：统一错误码与分类（GlobalExceptionFilter），对 Agent 友好可解析。

## 7. 安全与质量门禁

- **安全**：Helmet（CSP/HSTS/COEP/COOP）、全局 JwtAuthGuard + PAT、RateLimitGuard（throttler）、CORS 白名单、ValidationPipe（whitelist/transform）、敏感配置环境变量强制、GitHub webhook raw body HMAC 验签、CSRF 配置。
- **质量（根 `quality:gate`）**：`type-check` → `lint` → `test`（server swc/jest + frontend vitest）→ `contract:check` → server `test:e2e` → `api:audit --min=95` → `check:docs-sync`。
- **CI**：GitHub Actions `quality-gate.yml`（七并行 job + pnpm 缓存）、`release.yml`（发布）。
- **巡检护栏**：knip（未用依赖/导出）、dependency-cruiser（server 依赖边界）、`check:cli-contract`、`check:i18n-sync`、renovate、husky + lint-staged。
- **阻断策略**：文档不同步、验收证据缺失、api 覆盖率不达标不得合并。
